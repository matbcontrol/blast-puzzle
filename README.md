# Blast Puzzle

Прототип головоломки с механикой Blast на Cocos Creator 2.4.15 и TypeScript.

Играть в браузере: https://matbcontrol.github.io/blast-puzzle/ (десктоп и телефон). Параметр `?seed=42` в адресе повторяет ту же партию.

## Что сделано

Основное задание и все четыре дополнительных:

- клик сжигает группу соседних тайлов одного цвета (от двух), остальные падают, сверху досыпаются новые;
- счётчик ходов и очков, победа при наборе цели, поражение, когда кончились ходы или на поле не осталось групп;
- автоматическое перемешивание мёртвого поля, до трёх раз за уровень;
- бустер «бомба» сжигает квадрат вокруг клетки, бустер «телепорт» меняет местами два тайла;
- супер-тайлы за большие группы: сжигают строку, столбец, область или всё поле. Взрыв, задевший другой супер-тайл, запускает его.

Сверх задания, чтобы прототип игрался как игра:

- три звезды за уровень и полоса прогресса под счётом. После победы срабатывают супер-тайлы, оставшиеся на поле, а каждый оставшийся ход превращается в бонусную ракету, и так можно добрать звёзды;
- на тайлах группы, которая даст супер-тайл, виден значок этого супер-тайла, так что большой ход можно планировать;
- подсказка через 5 секунд бездействия, предупреждение, когда остаётся 5 ходов, и окно поражения с тем, сколько очков не хватило;
- частицы, ракеты, ударная волна, тряска поля, всплывающие очки, которые улетают в счёт, и процедурные звуки;
- тап во время анимации запоминается на 0,3 секунды и срабатывает, когда поле успокоится;
- раскладка под телефон и десктоп без полос по краям.

Физический движок не используется и выключен в сборке.

## Запуск

Редактор: в Cocos Dashboard нажать Add Project и выбрать папку репозитория. В корне лежат и `project.json` от Cocos, и `package.json` с npm-инструментами, поэтому Dashboard спросит версию, нужно выбрать 2.x. Без Dashboard проект открывается так: `CocosCreator.exe --path <папка>`. Сцена: `assets/scenes/Game.fire`.

Проверки:

```bash
npm ci
npm run check
```

`check` запускает проверку типов игры с API Cocos, проверку типов тестов и инструментов, ESLint и Jest (316 тестов). GitHub Actions на каждый пуш выполняет ту же команду.

```bash
npm run simulate
```

Боты играют уровень тысячу раз на настоящей модели и печатают распределение очков и звёзд (подробнее в разделе про баланс).

```bash
npm run assets
```

Заново генерирует эффекты, иконки интерфейса и звуки (`npm run art` и `npm run sfx` по отдельности). Генераторы сохраняют uuid в `.meta` и пишут файл только если байты изменились, поэтому повторный запуск ничего не меняет.

Сборка для веба:

```bash
CocosCreator.exe --path . --build "platform=web-mobile;debug=false"
```

## Архитектура

Три слоя, зависимости направлены только вниз:

```
view/   Cocos-компоненты: поле, аниматоры шагов, эффекты, звук, HUD, бустеры, окна
  │
app/    контроллер и состояния ввода
  │
core/   модель игры
```

В `core/` и `app/` нет ни одного обращения к `cc`, в том числе в типах. То же верно для чистых частей вью (раскладка поля, расчёт частиц, счётчик очков и другие). Их список один, `ENGINE_FREE` в `jest.config.js`: по нему Jest считает покрытие, а ESLint запрещает в этих файлах `cc`. Поэтому модель, контроллер и вся арифметика вью тестируются в Node без движка.

Как проходит ход:

1. `BoardView` переводит касание в клетку и отправляет сигнал `cellReleased` с клеткой, где палец коснулся, и клеткой, где отпустил.
2. Текущее состояние ввода решает, что это значит. `IdleInput` играет только клик (обе клетки совпадают), поэтому палец, проведённый по полю, ничего не сжигает. `BoosterAimingInput` берёт клетку, где палец отпущен, так что прицел можно поправить, не отрывая пальца.
3. `GameController` вызывает `BlastGame.tap()` или `useBooster()`.
4. Игра создаёт действие (`PlayerAction`), оно меняет поле. Затем игра сама досчитывает гравитацию, досыпку, очки, ходы и проверку мёртвого поля.
5. Наружу возвращается `TurnResult`: неизменяемый список шагов (сгорело, создан супер-тайл, упало, досыпалось, перемешалось) и новый прогресс.
6. `TurnPlayer` проигрывает шаги через аниматоры, по одному на тип шага. Падение и досыпка начинаются сразу, но каждый столбец ждёт, пока догорят его собственные тайлы (`ColumnGates`). Если анимация упадёт, поле перерисуется из модели и игра продолжится.

Модель всегда опережает картинку на один ход и остаётся источником правды.

Состояния ввода: `IntroInput` (тап пропускает баннер с целью), `IdleInput`, `BoosterAimingInput`, `TurnLockedInput` (запоминает последний тап в `TapBuffer`) и `LockedInput` после конца уровня. Каждое состояние само убирает свои подсветки в `exit()`. Ни одно состояние не видит контроллер целиком: команды, запросы к игре и подсветки приходят тремя узкими интерфейсами (`InputCommands`, `InputQueries`, `InputCues`).

Каждая партия получает токен отмены. Рестарт посреди анимации или бонусных ракет отменяет старый поток, и он не трогает новое поле.

### Где здесь SOLID

- S: у каждого класса одна работа. `GroupRules` знает, что такое группа, `dropTiles` сдвигает столбцы, `LevelProgress` считает очки, ходы и звёзды, `BurnResolver` разбирает цепные реакции. `BoardView` только собирает части поля: указатель, сцену тайлов, подсветки, тряску.
- O: супер-тайлы, бустеры и аниматоры подключаются регистрацией. Новый вариант добавляется классом и строкой в точке сборки, код хода и ввода при этом не меняется (примеры ниже).
- L: любая `BurnArea` подставляется туда, где ждут зону взрыва. Бомба-бустер и супер-тайл «бомба» используют один класс `RadiusArea` с разным радиусом.
- I: интерфейсы узкие. Аниматорам доступен только `TileStage`, контроллеру только порты из `GameViews.ts`. Звук разделён на `SoundPlayer` (его получают все вью) и `SoundSwitch` (его получает только кнопка звука).
- D: контроллер зависит только от портов вью и не знает компонентов Cocos. Модель получает свои части через конструктор из корня композиции. Синглтонов нет. Вью стартуют с нуль-объектами (`NoSound`, `NoEffects`) и работают и до подключения сервисов.

Конкретные классы собираются в трёх местах: `BlastGameFactory.ts` собирает модель, `GameBootstrap.ts` подключает к ней контроллер и раздаёт вью звук и эффекты (`wireServices`), `TurnAnimations.ts` собирает аниматоры шагов и облик каждого взрыва.

Паттерны: Command (`PlayerAction`), Strategy (`BurnArea`, `ScoreFormula`, `HintPolicy`, облики взрывов), State (состояния ввода), Observer (`Signal`), Object Pool (`TileNodePool`, `FxSpritePool`), Factory (`TileFactory`, `TapActionFactory`, `FinaleActionFactory`), Null Object (`NoSound`, `NoEffects`).

### Как расширять

Новый супер-тайл: класс с интерфейсом `BurnArea` и имя в `SuperKinds`. Дальше компилятор сам покажет, что ещё заполнить: зона в каталоге `BlastGameFactory.ts`, облик взрыва в `createBlastLooks`, похвала в `Praise.ts` и строка в `ROCKS` объявлены как `Record<SuperKind, …>`, и пропущенный вид не скомпилируется. Останется спрайт в списке `TileSkins` в инспекторе (его отсутствие игра покажет при старте) и правило в `assets/configs/level1.json`.

Новый бустер: класс с `targetCount`, `createAction()` и `previewCells()`, id в `BoosterIds`, строка `add` в фабрике, поле с числом зарядов в `LevelConfig`, `parseLevelConfig` и `level1.json`, кнопка в сцене и подпись прицела в `Texts`. Код ввода менять не надо: `BoosterAimingInput` собирает столько клеток, сколько просит бустер. Поэтому бомбе с одной целью и телепорту с двумя хватает одного состояния.

Новый тип шага хода: интерфейс в `TurnStep.ts` и аниматор в `createTurnPlayer`. Тест проверяет, что у каждого типа шага есть аниматор.

Все числа анимаций лежат в объектах настроек рядом с кодом, который их использует: длительности шагов хода в `Timings`, сила и масштабы в `Feel`, у каждого компонента свой `…Feel` (`HudFeel`, `PopupFeel`, `FxFeel`, `ControllerFeel` и другие). Общие формы твинов (пульс, встряска, нажатие, отскок) в `view/Tweens.ts`.

## Решения по спорным местам

- Группа сгорает от двух тайлов, как в Toon Blast.
- Очки. В нажатой группе k-й тайл стоит k × 10: два тайла дают 30, пять дают 150, десять дают 550. Тайлы, сгоревшие во взрыве, стоят по 10. Без этого разделения супер-тайл «всё поле» приносил бы около 41 000 очков за клик при цели в 3 200.
- Если цель набрана на последнем ходе, это победа.
- Клик по супер-тайлу тратит ход. Бустер тратит свой заряд, ход не тратит.
- Перемешиваний три на уровень. Каждое гарантирует, что после него есть ход: если случайная перестановка не дала группу, одна группа собирается обменом одноцветных тайлов. Четвёртое мёртвое поле означает поражение.
- Бомба бьёт квадратом (2R+1)×(2R+1), как в большинстве Blast-игр. У бустера R = 1, у супер-тайла R = 2.
- Супер-тайлы по размеру группы: от 6 строка или столбец, от 8 бомба, от 10 всё поле. Значок на группе берётся из тех же правил и случайных чисел не тратит, поэтому подсказки и значки не меняют партию.
- Подсказка сначала показывает группу, которая даст супер-тайл, потом готовый супер-тайл, потом самую большую группу. Если показывать первый попавшийся супер-тайл, подсказка подталкивала бы тратить его впустую.
- Телепорт отказывается менять местами два одинаковых тайла, и подсветка прицела гаснет над такой клеткой заранее. Если отказ всё же случился, первый выбранный тайл остаётся выбранным.
- Звёзды: одна за цель, две за 3 750, три за 4 400. В бонусном раунде сначала бесплатно взрываются супер-тайлы, которые игрок не потратил, потом каждый оставшийся ход становится ракетой. Очки за них считаются как за обычные взрывы. Так сохранённый супер-тайл всё равно приносит очки.
- Похвала привязана к событиям модели: «Отлично!» за заработанную бомбу и второй взрыв в цепочке, «Супер!» за заработанное поле и третий взрыв, «Невероятно!» за взрыв всего поля. Не больше одного слова за раз.
- Окно результата перехватывает касания, пока открыто, а новая партия раздаётся только после того, как окно погасло. Так второй тап двойного клика не попадает в новое поле.
- Генератор случайных чисел с сидом (mulberry32) передаётся в модель снаружи. Одинаковый сид даёт одинаковую партию, отсюда воспроизводимые тесты и `?seed=` в адресе. В продакшене это же позволило бы проверять ходы на сервере.

Все числа уровня лежат в `assets/configs/level1.json`, при загрузке они проверяются, и ошибки выводятся списком. Затем `GameBootstrap` сверяет уровень со сценой: у каждого цвета и супер-тайла должен быть спрайт в `TileSkins`, у каждого бустера ровно одна кнопка. Расхождения тоже выводятся списком, и игра не стартует.

## Баланс

Цель, число ходов и пороги звёзд подобраны симуляцией (`npm run simulate`, 1000 партий на стратегию). Боты играют на настоящей модели, допустимый ход берут из `GroupRules.canTap`, бустеры не используют:

| Бот                           | Медиана очков | Цель 3200 за 30 ходов | Две звезды | Три звезды |
| ----------------------------- | ------------- | --------------------- | ---------- | ---------- |
| случайный                     | 2630          | 22%                   | 18%        | 9%         |
| жадный (самая большая группа) | 3770          | 78%                   | 49%        | 17%        |

Звёзды считаются вместе с бонусным раундом. Жадный бот сразу взрывает каждый супер-тайл, случайный часто оставляет их на поле, поэтому бонусный раунд прибавляет ему больше.

## Производительность

Замеры в сборке web-mobile:

- 15 draw calls в покое, до 18 во время хода и до 20 в самый тяжёлый момент бонусных ракет с конфетти. Тайлы попадают в Dynamic Atlas, поэтому 90 тайлов не дают 90 вызовов. Статичный текст кэшируется в тот же атлас, меняющиеся числа в общий атлас символов. Глифы похвалы и чисел рисуются в атлас при загрузке, чтобы первая похвала не подтормаживала посреди взрыва.
- Ноды тайлов берутся из пула. Отпущенный тайл остаётся под своим слоем с нулевой прозрачностью, без перевешивания в дереве. Спрайты эффектов заранее создаются при загрузке (396 на поле и 140 конфетти). Тест проигрывает девять цепочек взрывов на настоящей системе частиц и проверяет, что посреди цепочки не создаётся ни одного нового объекта и что каждому тайлу хватает частиц.
- Сборка весит 1,89 МБ, из них движок 762 КБ. Неиспользуемые модули движка выключены. Фон пережат в JPG: прозрачности у него нет, 704 КБ превратились в 50 КБ.
- Звуки (17 WAV, 299 КБ) лежат в бандле `resources` и грузятся после первого кадра, поэтому сцена не ждёт их загрузки. Звук, который ещё не пришёл, просто не играет.
- Экран: на высоком телефоне фиксируется ширина, на широком окне высота. HUD прибит к верху, бустеры к низу, поле растёт в освободившуюся высоту до 96% ширины, фон растягивается на остаток (`ScreenFit`, `CoverBackground`). Полос по краям нет, поле всегда видно целиком.

## Особенности Cocos 2.4.15, о которые я споткнулся

- Редактор компилирует TypeScript 4.1 через `transpileModule`, без проверки типов. Синтаксис новее (`satisfies`, `override`) в нём не работает, а `for..of` по `Map` и `Set` молча выполняется ноль раз. `npm run typecheck` с target ES5 ловит такой `for..of`. ESLint запрещает синтаксис новее 4.1, потому что `tsc` и Jest здесь работают на TypeScript 5 и сами его пропустят.
- В `creator.d.ts` из поставки 2.4.15 не хватает запятой (строка 20916), и из-за этого `tsc` не проверяет семантику вообще. Исправленная копия лежит в `types/creator.d.ts`.
- Если в `builder.json` стоит ориентация `portrait`, шаблон web-mobile поворачивает игру на десктопе. Поэтому стоит `auto`, а портретную раскладку держит `ScreenFit`.
- Без `project.json` Dashboard по `package.json` записывает проект как 3.x и потом не перепроверяет. Если проект уже добавлен с неправильной версией: удалить его из списка с сохранением файлов и добавить заново.
- `cc.easing` живёт в модуле Animation. Если выключить этот модуль в настройках сборки, твины с easing падают при первом вызове.
- На телефонах `touchstart` не считается жестом пользователя для звука, поэтому звук разблокируется на `touchend`. Звуки, запрошенные, пока контекст просыпается, придерживаются и играют после разблокировки, если им не больше 150 мс. Проверка поддержки читает приватное поле `cc.sys.__audioSupport`, привязанное к версии 2.4.15, и при его отсутствии пишет предупреждение.

## Ассеты

Графика блоков, рамок и кнопок из макета задания. Эффекты (свечение, искры, осколки, кольцо, конфетти), иконки звука, звёзды, полоса прогресса и плашка сообщений нарисованы кодом в `tools/art`. Звуки синтезированы кодом в `tools/sfx`. Шрифт в макете Marvin, он платный, поэтому вместо него Rubik Black под лицензией OFL (`assets/fonts`).

## Что можно сделать дальше

- Уровни с разными целями (собрать N тайлов цвета, разбить препятствия): цель уровня уже отделена от правил хода.
- Сохранение прогресса и карта уровней.
- Сжатый звук. WAV оставлен потому, что MP3 добавляет около 50 мс тишины в начале коротких звуков, а Ogg не играет в старых Safari.
